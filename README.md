# 话匣子 · chatterbox

[![CI](https://github.com/Minazuki26710/chatterbox/actions/workflows/ci.yml/badge.svg)](https://github.com/Minazuki26710/chatterbox/actions/workflows/ci.yml)

> 让 AstrBot 在 QQ 群里像群友，而不是像客服：会潜水、会被叫到才说话、会自己找话题、会闭嘴。

一个给 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 用的群聊行为插件。核心不是"让机器人更会说话"，而是**让它学会什么时候不说话**——这是现有群聊机器人最容易做砸的地方。

**当前状态：v0.19.2。** 面向 AstrBot 的群聊行为插件；配置项与默认值以 `_conf_schema.json` 和本文为准。

**当前版本未经真机验证，U1-U6 尚未验收。** 核心逻辑与静态检查通过，但尚未在干净的 AstrBot 环境中完成安装、群聊和媒体链路验证；用于生产前请自行在测试群灰度。

## 它解决什么问题

默认的 AstrBot 在群里只有两种模式：不响应，或者每条都响应。真实群聊不是这样——大部分消息不需要你接，但冷场了又需要有人开口。

话匣子把这件事拆成三层：

| 层 | 做什么 | 靠什么 |
|---|---|---|
| 状态 | 潜水 / 活跃 / 休眠 / 探话 四态流转 | 被 @ 进活跃，静默久了回潜水，可配置休眠时段 |
| 决策 | 这条消息要不要接 | 独立小模型判定 REPLY / SKIP，带人格上下文 |
| 克制 | 说话也不能刷屏 | 闸门限流 + 最小间隔 + 潜水态新消息门槛 |

## 特性

- **四态状态机**：潜水（默认）→ 活跃（被叫到，30 分钟）→ 休眠（可选时间窗，默认关闭）→ 探话（冷场时主动开口）。
- **被 @ / 引用必回**（受闸门限流，超配额静默丢弃），并引用那条消息；回复走 AstrBot 正常管线，人格、长期记忆、知识库、工具等能力（如你已在 AstrBot 启用）自动生效。
- **主动接话走判定模型**：一个便宜的小模型看最近若干条群聊，决定接还是不接，默认附一句理由（可关）。
- **冷场开话题**：群里静默到点，按概率主动起一个话头，自己分段发。
- **读图 / 语音 / 合并转发**：图片和语音后台串行转述，判定不等识图；转述结果按 URL 缓存。读图、读语音默认关闭（避免你没打算花的模型调用），需要时在配置里开启。
- **每群启停**：配置 `groups` 圈定管理范围后，每个群可以在面板上单独停用/启用，插件自己持久化，不依赖其他插件。
- **不多吃 token**：可选地不携带 AstrBot 的会话历史，群聊上下文只靠注入的最近 N 条，以及你已启用的其他能力（如长期记忆）。
- **可视化面板**：每个群的状态、最近判定流水、闸门用量、发言档案（这条回复用了哪些上下文，以及可选的记忆/知识库信息）。

## 安装

> 仓库根就是插件目录（`main.py`、`metadata.yaml` 都在根上），整个仓库直接放进 AstrBot 的插件目录即可。

```bash
cd <AstrBot>/data/plugins/
git clone https://github.com/Minazuki26710/chatterbox.git
```

重启 AstrBot，在面板里启用 `astrbot_plugin_chatterbox`。

要求：AstrBot `>=4.29,<5`，平台 `aiocqhttp`（QQ）。开启读语音后还需要 `ffmpeg` 在 PATH 里。

## 最少要配什么

装上之后**不会自己说话**，按顺序做三步：

1. `groups`：填要管理的群号（`[]` = 未配置，插件不会在任何群生效；单个群可在面板上停用）。
2. 判定模型：`decision.judge_provider_id` 可以**留空**，默认跟随会话当前在用的对话模型；想省钱或提速时再单独指定一个便宜的小模型。
3. 打开面板确认：默认开启「主动发言影子」，只判定不主动说话（被 @ / 引用仍正常回复）。观察日志里的 REPLY/SKIP 理由合理后，在面板点「切换主动发言影子」关闭，机器人才会主动接话。

人格是可选能力：插件不自带人格，判定时读取当前会话的人格设定；没配人格也能工作，只是表达更中性。长期记忆、知识库等能力同样可选，需要你自行在 AstrBot 启用，本插件不依赖它们。

想让它被叫名字也应答，可在 `decision.bot_names` 填名字/外号，例如 `小明,小明明`；留空时只响应 @ 和引用，不会因为名字误触发。

其余 7 组配置（状态、休眠、上下文、判定、探话、闸门、调试）都有默认值，`_conf_schema.json` 里有逐项说明。

## 默认值是保守的

默认值刻意保守：潜水态 3 分钟看一次群、闸门 5 分钟 3 条、活跃态 35% 概率开口。闸门、概率和最小间隔会叠加，同时放宽会明显变吵，调参前先理解这几项的相互关系。

## 它是怎么工作的

- 设计取舍与里程碑：[docs/DESIGN.md](./docs/DESIGN.md)
- 判定链路与提示词细节：待补（`docs/judge-pipeline.md`）

一句话版本：群消息进群 → 按类型分流 → 过一系列克制关卡 → 小模型判 REPLY/SKIP → 通过就 `event.request_llm()` 交给 AstrBot 管线生成 → 加引用、分段、发出去。

关键设计决策：**主动发言不自己拼提示词**，而是复用 AstrBot 的聊天管线。这样人格、记忆、工具都不用插件再实现一遍，代价是控制粒度变粗。

改代码前建议先看 `core/presence.py`（状态机）和 `core/decide.py`（判定），这两个文件决定行为。

## 已知限制

- 状态只在内存：插件重载或进程重启，所有群回到潜水，冷却和活跃时间全部清零。
- 探话内容容易重复：群里静默时输入几乎固定，模型会反复说同一句。
- 判定上下文里带着机器人自己的发言，小模型容易因此判"刚刚说过话，不回"。
- 英文界面不完整：日志、指令回复、默认提示词都是中文。
