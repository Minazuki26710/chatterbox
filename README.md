# 话匣子 (astrbot_plugin_chatterbox)

[![CI](https://github.com/Minazuki26710/chatterbox/actions/workflows/ci.yml/badge.svg)](https://github.com/Minazuki26710/chatterbox/actions/workflows/ci.yml)

面向 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 的 QQ 群聊行为控制插件。通过状态机、独立模型判定与多级频控闸门，管理机器人在群聊中的发言时机与频率。

- **当前版本**：`v0.19.2`（配置项与默认值以 `_conf_schema.json` 及本文档为准）
- **验证状态**：**当前版本未经真机验证，U1-U6 尚未验收。** 核心纯逻辑单测与静态检查已通过，但尚未在干净的 AstrBot 环境中完成安装、群聊事件与媒体链路的真机验收；投入生产群前请先在测试群灰度验证。

---

## 背景与定位

AstrBot 默认的群聊响应通常只有“仅唤醒时回复”或“全量响应”两种模式。在实际群聊场景中，全量响应容易刷屏，仅靠 `@` 唤醒则缺乏主动参与感。

本插件在 AstrBot 原有对话管线前增加一层群聊行为调度，拆分为三个部分：

| 模块 | 职责 | 核心机制 |
|---|---|---|
| **状态流转** | 控制判定节流间隔与行为边界 | 潜水 / 活跃 / 探话 / 休眠四态独立维护，按群隔离 |
| **接话决策** | 判断当前群聊是否适合插话 | 独立判定提示词与模型输出 `REPLY` / `SKIP` 及理由 |
| **频控克制** | 防止连续抢话与刷屏 | 滑动窗口配额闸门 + 最小发言间隔 + 潜水新消息门槛 |

主动发言确定触发后，插件通过 `event.request_llm()` 复用 AstrBot 标准对话管线生成回复，无需重复实现人格、长期记忆、知识库或工具调用逻辑。

## 功能特性

- **四态群聊状态机**
  - **潜水（`dive`）**：默认状态。新消息到达时按 `dive_tick_min` 节流（默认最多每 3 分钟判定一次），且水位线之后的新消息达到门槛（默认 5 条）才触发接话判定。
  - **活跃（`active`）**：被 `@`、引用回复或提及名字时进入（默认持续 30 分钟，每次触发续期 3 分钟，单次活跃硬上限 120 分钟）。新消息到达时按 `active_tick_sec` 节流（默认最多每 30 秒判定一次），先掷发言概率再执行判定。活跃到期后回落潜水并进入冷却期。
  - **探话（`probing`）**：活跃态下群聊静默达到设定时长（默认关闭），按概率主动抛出话题并进入观察窗口；窗口内有人接话则恢复活跃，超时无人回应则回落潜水。
  - **休眠（`sleep`）**：支持定时窗口（默认关闭）或指令手动锁定。休眠期间不判定、不主动发言；群消息仍实时写入上下文缓冲，媒体转述按 `sleep.read_tick_min` 低频补充；被 `@` 或引用时仍正常回复，但不进入活跃态。
- **被动唤醒与自动引用**：
  - **被 `@` 或引用**：通过频控闸门后直接进入 AstrBot 回复管线（不调判定模型）。
  - **提及设定昵称（`decision.bot_names`）**：通过频控闸门后先执行一次强制判定（不受节流间隔与新消息条数门槛限制），判定为 `REPLY` 且未开启影子模式时，再通过 `event.request_llm()` 进入回复管线。
  - 以上唤醒回复均在消息头部自动插入对原消息的引用；超出闸门配额时静默丢弃。
- **独立接话判定**：将近期群聊拆分为「当前话题」与「更早背景」两段提交给判定模型，输出 `REPLY` 或 `SKIP`（默认附带简短理由）。支持单独指定低成本判定模型与浓缩版判定专用人格。
- **多模态上下文按需转述**：
  - **合并转发**：默认开启，调用平台 `get_forward_msg` 接口展开转发内容（默认最多 20 条 / 600 字，不消耗模型额度）。
  - **图片与语音**：默认关闭（避免产生未预期的视觉/STT 模型调用与费用）。开启后由后台队列串行转述为文本并注入上下文，结果按 URL/文件标识持久化缓存，不阻塞判定流程；支持自动识别并跳过商城/收藏表情包（记为 `[表情]`）。
- **会话历史裁剪**：支持裁剪或清空 AstrBot 默认携带的长会话历史（`context.history_messages` 默认为 `0`），改由插件注入最近 N 条群聊记录（默认 30 条），降低活跃群聊的 Token 消耗。
- **单群独立启停**：在 `groups` 配置管理范围后，可在可视化面板对单个群独立启用或停用，状态由本插件自行持久化。
- **可视化管理面板**：内置 Web 面板，展示各群实时状态、闸门用量、最近 40 条判定流水、最近 20 条发言档案（支持查看触发时的上下文条数、已启用的长期记忆召回片段，以及按需复算知识库检索结果）。

## 环境要求与安装

### 环境要求

- **AstrBot**：`>=4.29,<5`
- **消息平台**：`aiocqhttp`（OneBot v11 协议端，如 NapCat、Lagrange 等）
- **可选依赖**：开启语音转写（`context.read_voice = true`）时，运行环境 `PATH` 中需安装 `ffmpeg`

### 安装方式

仓库根目录即插件目录（`main.py` 与 `metadata.yaml` 位于根目录），直接克隆至 AstrBot 插件目录即可：

```bash
cd <AstrBot>/data/plugins/
git clone https://github.com/Minazuki26710/chatterbox.git
```

克隆完成后重启 AstrBot（或在 WebUI 插件管理页重载插件），启用 `astrbot_plugin_chatterbox`。

## 快速开始（最小配置）

插件默认配置为 `enabled=true`、`groups=[]`（不在任何群生效）、`debug.shadow_mode=true`（只判定不主动发言）。按以下三步完成最小配置：

1. **填写管理群号（`groups`）**
   在插件配置中添加需要接管的 QQ 群号（默认 `[]` 表示未配置，插件不在任何群生效）。建议先填写单个测试群进行灰度。
2. **确认判定模型（`decision.judge_provider_id`）**
   可保持留空，留空时默认跟随该群当前会话使用的对话模型；若希望降低判定耗时与成本，可下拉指定一个轻量模型。
3. **验证并关闭主动发言影子模式（`debug.shadow_mode`）**
   默认开启「主动发言影子模式」：插件会正常捕获上下文、执行 `REPLY / SKIP` 判定并记录日志，但**不会真正发送主动接话与探话消息**（被 `@` 或引用仍由 AstrBot 正常回复）。在插件面板观察「判定流水」确认表现符合预期后，点击面板顶部的「切换主动发言影子」将其关闭，机器人即开始主动发言。

### 可选能力说明

- **昵称唤醒（`decision.bot_names`）**：默认留空，仅响应 `@` 与引用消息。如需提及名字也触发判定与回复，可填写逗号分隔的昵称（如 `小明,小明明`）；该回复同样受主动发言影子模式约束。
- **人格、长期记忆与知识库**：本插件不自带人格与记忆存储。判定时会读取当前会话在 AstrBot 中配置的人格（未配置时使用中性群友设定，且通用判定规则优先于人格设定）；回复时若已在 AstrBot 启用长期记忆、知识库或工具能力，均会自动生效。

## 管理员指令

以下指令需群聊管理员权限，且仅在已列入管理范围（未停用）的群聊中生效：

| 指令 | 说明 |
|---|---|
| `/chatterbox` | 查看当前群的心跳计数、当前所处状态（潜水 / 活跃 / 探话 / 休眠）及剩余时长 |
| `/onair` | 手动切入活跃态（已在活跃态则延长活跃时间；若处于休眠则解除休眠，并覆盖定时休眠窗口直到再次手动切换） |
| `/lurk` | 手动退回潜水态（解除休眠并覆盖定时休眠窗口直到再次手动切换；进入冷却期，期间仅响应 `@`/引用而不重新激活） |
| `/offair` | 手动锁定休眠态（暂停主动判定与主动发言，被 `@`/引用照常回复；不受定时窗口结束影响，需发 `/onair`、`/lurk` 或在面板点击「解除休眠」退出） |

## 配置项概览

完整参数定义与字段提示见 `_conf_schema.json`。除顶层开关（`enabled`、`groups`、`disabled_groups`）外，共分为 7 组：

| 分组 | 关键参数与默认值 | 说明 |
|---|---|---|
| **状态机 (`state`)** | `dive_tick_min=3.0`、`dive_min_new_msgs=5`、`active_tick_sec=30.0`、`active_ttl_min=30.0`、`extend_per_trigger_min=3.0`、`extend_cooldown_min=5.0`、`active_max_min=120.0`、`active_speak_gap_sec=25.0` | 控制潜水/活跃的判定节流间隔、活跃时长、续期步长、硬上限冷却及两次发言的最小时间间隔 |
| **休眠时段 (`sleep`)** | `enabled=false`、`start="00:00"`、`end="08:00"`、`read_tick_min=30.0` | 按 AstrBot 服务器本地时间计算的定时休眠窗口（支持跨午夜）；休眠中消息仍写入缓冲，仅按间隔低频补充媒体转述 |
| **上下文注入 (`context`)** | `ctx_messages=30`、`history_messages=0`、`recent_split=8`、`read_images=false`、`read_voice=false`、`read_forward=true` | 控制群聊缓冲注入条数、会话历史保留条数，以及图片/语音/合并转发的转述开关、模型与缓存 TTL |
| **决策 (`decision`)** | `judge_enabled=true`、`judge_in_active=true`、`speak_prob_active=0.35`、`bot_names=""`、`use_persona=true` | 控制判定开关、活跃态发言概率、判定模型 ID、唤醒昵称、判定专用人格及自定义提示词 |
| **冷场主动开话题 (`probe`)** | `enabled=false`、`probe_idle_min=10.0`、`probe_prob=0.6`、`probe_wait_min=4.0`、`lines_per_hour=6` | 控制活跃态下静默多长时间尝试开启话题、观察窗口时长、冷却间隔及每小时总发言上限 |
| **发言限流 (`gate`)** | `gate_window_sec=300`、`gate_max=3` | 滑动时间窗口内的最大发言条数（主动接话与被动回复共用配额，超额静默丢弃） |
| **调试 (`debug`)** | `shadow_mode=true`、`verbose_log=true`、`trace_max_items=100` | 控制主动发言影子模式、详细日志输出及发言档案最大保留条数 |

> **调参提示**：默认参数偏向保守。发言闸门（`gate`）、活跃发言概率（`speak_prob_active`）与最小发言间隔（`active_speak_gap_sec`）共同约束发言频率，不建议同时大幅放宽多项阈值。

## 工作原理

早期设计稿参见 [docs/DESIGN.md](./docs/DESIGN.md)（历史设计稿，具体参数与触发链路以当前代码和 `_conf_schema.json` 为准）。核心执行链路如下：

1. **消息捕获**：群消息到达时，先校验是否为受管群，忽略私聊、机器人自身消息与插件指令；将文本、提及标记及媒体标识写入该群的环形上下文缓冲，并按配置将图片/语音/转发投递至后台转述队列。水位线用于标记已处理到的消息，只在实际发言或管线回复后推进，未回复时保留待下次判定。
2. **被动触发通路**：
   - **被 `@` 或引用**：更新状态机（非休眠时进入活跃或续期）→ 检查发言闸门配额 → 放行后直接交由 AstrBot 标准管线处理（不调判定模型）。
   - **提及设定昵称**：更新状态机并检查发言闸门配额 → 放行后先执行一次强制判定（`force=True`），判定为 `REPLY` 且非影子模式时通过 `event.request_llm()` 进入标准管线。
   - 进入管线的请求在 `on_llm_request` 阶段裁剪会话历史并注入 `<group_context>`，在 `on_decorating_result` 阶段插入 `Reply` 引用并按需兜底分段，回复完成后推进水位线。
3. **消息驱动的判定通路与后台心跳**：普通群消息到达时按当前状态节流（潜水默认 3 分钟/次、活跃默认 30 秒/次）→ 校验休眠状态、闸门配额与最小发言间隔 → 若水位线之后有新消息且满足门槛（潜水态需满 `dive_min_new_msgs` 条，活跃态需先通过 `speak_prob_active` 概率），调用判定模型获取 `REPLY / SKIP` → 若判定为 `REPLY` 且未开启影子模式，通过 `event.request_llm()` 发起主动接话并推进水位线（生成期间若群内出现新的唤醒触发，当前主动生成结果自动作废）。后台每秒心跳只负责维护状态到期、休眠窗口切换和冷场探话调度。

## 开发与测试

项目将纯业务逻辑与 AstrBot 框架适配层分离：
- `core/`：配置解析与持久化（`config.py`）、指令识别（`commands.py`）、状态机（`presence.py`）、接话判定（`decide.py`）、上下文缓冲与渲染（`ctx.py`）、频控闸门（`gate.py`）、合并转发解析（`forward.py`）、分段切分（`segment.py`）、缓存（`cache.py`）与档案（`trace.py`），均不依赖 AstrBot 运行时。
- `modules/`：消息捕获（`capture.py`）、人格读取（`persona.py`）、视觉转述（`vision.py`）与消息发送（`speak.py`）。

运行单元测试（仅依赖 Python 标准库，无需启动 AstrBot 或安装 `pytest`）：

```bash
python tests/test_core.py
```

当前共包含 281 项纯逻辑断言测试。`main.py` 中的事件钩子与平台交互链路需在 AstrBot 环境中通过真机测试验证。

## 已知限制

- **状态未持久化**：群状态机（活跃剩余时间、冷却时间戳、闸门计数、上下文环形缓冲）保存在内存中，插件重载或进程重启后所有群重置为潜水态。
- **探话内容重复度**：当群聊长时间静默、近期上下文固定不变时，多次触发冷场开话题可能生成相近的内容。
- **自身发言对判定的影响**：近期上下文中包含机器人自身的历史回复，部分轻量判定模型可能倾向于判定“刚刚发过言”而连续输出 `SKIP`。
- **语言支持**：面板界面、日志输出、管理员指令回显及内置提示词目前仅提供中文。
